## 2. The stories

Each one is a script in `scripts/class/stories/`, run against the real teacher's side over real sockets on one
computer, with the exam's clock running 10 or 20 times as fast.

| Story | Result |
|---|---|
| 30 students join, start and hand in → 30 receipts (the same on both sides), 30 folders, the log complete | ✅ |
| A student kills ExamMode → *left (stopped suddenly)*; joins from another PC → refused, waiting; Let back in → in the exam there; hands in | ✅ |
| The network drops for 45 s → *no contact*, then *in the exam* with the gap and the lab computer's own record of it; the work written meanwhile is handed in | ✅ |
| Time up → every student handed in, marked *time up* | ✅ |
| A wrong code and a name already taken are refused | ✅ |
| ExamMode crashes in the lobby before Start → the student joins again normally | ✅ |

`npm run class -- --students 30 --minutes 10 --speed 20` shows a whole lesson with random network drops, a kill and
early hand-ins, and prints the log as the live view will show it.

## 3. For the teacher

**Things I decided that the documents didn't say. Each needs your yes or no:**

| # | Case | What I made it do | Why |
|---|---|---|---|
| 1 | **Five wrong codes** from one computer | It waits one minute before it can try again | The code has four digits: without this, a program could try all 10 000 and join from another room (F-03) |
| 2 | **The class list** on the join screen | A lab computer gets the names before the code is typed, as the prototype's screen 01 shows. An email is shown only where two students have the same name | Screen 01; and no more of the class's details on the network than needed (N-09) |
| 3 | **Time up** on a lab computer whose clock isn't quite the teacher's | At the end by its own count, ExamMode stops and waits up to 5 s for the teacher's laptop to say *time is up*; then it hands in. Marked *time up*, as is any hand-in in the last 2 seconds | The teacher's laptop decides (D5); a clock that is a little ahead mustn't turn *time up* into *handed in* |
| 4 | **A file backed up, then deleted** (or put back as it was given) before the hand-in | The hand-in is what the student handed in. The older backup is kept beside it, in *Earlier backups* in their folder | Nothing the teacher's laptop received is ever thrown away (N-05) |
| 5 | **Leave** | The work so far is sent first, then *left*. If the teacher's laptop couldn't take it (no network), the Exam folder stays on the lab computer | F-15, F-21: the folder is removed only once the teacher has the work |
| 6 | **Hand in with no network** | ExamMode keeps trying, and the hand-in goes through when the network is back. It is *handed in* at the time it arrives | F-19 |
| 7 | **Time up while a student has no contact** | Their ExamMode stops at the end by its own count and hands in when the network is back (*time up*). Until then the teacher sees *no contact* | F-17, F-19 |
| 7b | **The power going on the teacher's laptop** | Start, every hand-in and the end are on the disk for good before anyone is told (a receipt is given only then); other lines of the log may lose their last second | Writing every line for good made 40 students joining at once take longer than 2 s on a slow computer (N-03) |
| 8 | **Let back in** for a student whose ExamMode is waiting | It hears *joined* and is in the exam at once, on the computer it asked from. The separate *let back in* message is gone from the protocol | One message less to get wrong |
| 9 | **Lock files** (`~$Report.docx`, `Thumbs.db`, `.DS_Store` …) | Never backed up or handed in | They aren't the student's work, and Word keeps them open |
